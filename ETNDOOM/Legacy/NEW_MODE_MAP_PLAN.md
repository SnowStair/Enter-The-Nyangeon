## 1. Existing Entry / 现有入口与范围

- 原生 `ModManager` 加载新模式模组；模组 entry 可创建自带模式场景或接管 `ExtensionHooks.change_scene_gate`。拦截成功会同时跳过原版切场景与玩家初始化，模组须完成所需后续流程（`script/mod_manager.gd:942-960`、`script/GameEvents.gd:184-205`）。
- 现有 `KIND_CLASS` 没有 `maps` 类型，不能靠新增 `defs/maps/` 获得原生地图注册；新模式应有自己的地图目录与加载层（`script/mod_manager.gd:29-39,591,684`）。
- 不实例化原版刷怪、突袭与导航相关运行节点；本体常驻单例仍在，须核对新模式进入、退出时的信号、输入、暂停与时间状态。尤其不能只关 `_process` 就认为停用了 `MapBounds`（`script/map_bounds.gd:23-51`）。
- 角色、敌人和攻击中直接依赖二维屏幕位置的部分仍须适配高度模型。美术、数值与部分结算可按实际依赖复用；原版内容完整兼容列为后续工作，不作为第一版空间验证的前提。
- 用户明确（2026-10-24，来源：user）：阶段 5/7 的敌怪为适配 DOOM 地图与 DOOM 的逻辑，将大幅重做或直接新设计。新实体管理应面向这些行为，不以整体接管原版敌怪运行逻辑为目标；素材及独立配置按需复用。阶段 0 的 Momoi 玩家实体复用单独处理。

## 2. Responsibilities / 职责划分

以下为建议名称与职责，不是已有类：

| 层 | 职责 |
|---|---|
| `ModeSession` | 管理一局的进入、运行、结束、退出；决定规则、难度与敌人组合 |
| `MapCatalog` | 发现可用地图，提供稳定地图 ID、名称、版本与兼容信息 |
| `MapLoader` | 读取地图包、校验数据与资源，生成统一的 `MapDefinition` |
| `MapDefinition` | 保存精确静态地形、原始 mu 高度、边界、障碍、装饰和出生区域；不保存一局中的实体状态或普通跨步授权标签 |
| `MapRuntime` | 根据定义创建表现与空间服务，管理本次地图实例及派生碰撞、导航数据 |
| 实体与战斗 | 使用逻辑平面位置和高度；通过空间服务查询地形、通行与遮挡 |
| `SpawnDirector` | 根据模式规则选敌人、数量和时机，再查询地图上的合法出生位置 |

关系为：原生加载器加载新模式模组；新模式的地图加载器读取独立地图包。更换地图不应要求重新构建模式模组。

地图可声明出生区域和用途标签，如 `player_start`、`enemy_spawn`、`raid_entry`；普通与突袭刷怪可在后续阶段消费相应配置。用户于 2026-11-12 确认最小地图必须含玩家出生点，其它出生点/区域/标签均非必需，D09 整体已决策：读取与选择规则见阶段 1 契约 §3.14，不检测玩家出生合法性；高度初始化按 §3.15 采用 UZDoom 占地抬高与撞顶下压，接受重叠及卡住，中心无真实地面则告警并取玩家脚底 0mu，不伪造地面。地图不要求四个固定方位，也不规定整局的刷怪节奏。模式可根据需要提供独立遭遇配置，以地图 ID / 区域标签关联。

## 3. Spatial and Data Contract / 空间与数据约定

### 3.1 第一版空间规则

- 逻辑位置采用平面 `(u,v)` 与独立世界高度 `h`，地面由后续实现的 `H(u,v)` 查询。阶段 0.3 已验收的基线为 `(u,v,h)=(wad_x,-wad_y,wad_height)`、表现世界 `(u,h,v)`、平面 `1 logical unit = 1mu`，以单一正交 `Camera3D` 投影；`yaw=45°`、`pitch=45°` 下正方形地面为 `√2:1` 菱形。导航距离、出生距离与攻击距离使用逻辑空间。
- 用户确认（2026-11-01）：不采用规则地形网格或固定高度等级；保留 WAD 的精确 sector 形状与直接 mu 高度，无 sector 区域统一为无地面。静态楼梯只是多个不同高度的 sector，玩家最大向上跨步 `24mu`，在尝试移动时结合当前脚底高度和实际几何判定；不要求显式楼梯连接/授权，也不把按高度差算出的可通行标签写入相邻区域。SUPERSEDED: 墙体后于 2026-11-06 按 D05、离地/下坠后于 2026-11-05 按 D04 正式决策；敌人能力仍归阶段 5。SUPERSEDED: 原“离散高度平台与明确楼梯连接”的建议被本次用户修正取代。
- 站立时脚底高度与地面一致；离地后世界高度独立积分，不能每帧把当前位置地面高度加到跳跃偏移上，否则经过悬崖或高台会错误跟随地面。

## 5. Milestones / 验收目标

首个验收目标阶段 0 已完成：0.1 无碰撞矩形地图渲染、0.2 同图真实外框碰撞、0.3 侧方正交视角及五图回归均已通过对应验收，Gate A–D 已完成；全程固定 Momoi 且没有其他玩法实体。当前阶段 1 的目标是承接这些成果，冻结新增规则并给出完整示例数据。

后续首个战斗闭环目标保持不变：从外部加载一张低地、高台、楼梯和内部障碍组成的地图；一个角色、一个敌人、一种武器、一种区域刷怪；能结束、重开与退出。随后以布局不同的第二张地图验证通用性。以下为该后续目标的验收标准，不是阶段 0 的前置要求。

- 新增第二张地图仅增加数据和素材，不增加地图专用脚本。
- 玩家能按约定上下高台，敌人能追踪；高度与墙体阻挡攻击的结果符合规则。
- 地图没有合法出生点或目标不可达时不会陷入无限循环。
- 地图准备顺序为读取、校验、构建地形 / 碰撞 / 导航、确认就绪，再生成实体并启动计时；失败时不留下半初始化战斗。
- 切图或退出停止调度，释放本次地图与实体引用，并清理订阅；重复进入不会把旧地图回调应用于新地图。
- 最终在未修改的游戏发布包加模组环境中验收；本设计文档不代表这些效果已运行验证。
