## 1. Boundaries / 已知边界

- 现行顺序为阶段 0.1 无碰撞矩形平地图 → 阶段 0.2 同图真实边缘碰撞 → 阶段 0.3 侧方正交投影 → 阶段 1 契约细化。阶段 0 已验收，不补做高台、楼梯、敌人或战斗作为交接前提。
- 地形是不叠层伪 3D：同一平面位置最多一个可站立地面。没有定义 sector 的区域统一表示为无地面，不按“地图外/地图内空洞”分型。保留精确区域形状与直接 mu 高度，不引入规则地形网格或固定高度等级（2026-11-01，来源：user）；边界归属、查询细则与数值表示于 2026-11-04 按 D01/D02 正式选定。
- 用户确认（2026-11-04）：ETNDOOM 使用 WAD 预存 BSP，不引入构建器；随后正式确认 D01–D03 的下述方案。读取、校验、运行时树和查询仍须实现；不采用逐位复刻 DOOM 算术，首版节点格式按 D07 §3.12 D07-05 已确定；REJECT 已于 2026-11-12 确认阶段 1 不使用；BLOCKMAP 已另行决定暂不使用，即使 WAD 含该数据也不启用。
- 游戏本体与原生模组加载器不变；新模式模组自行提供地图加载层。原生 `KIND_CLASS` 没有 `maps` 类型，不能假设新增 `defs/maps/` 就能加载地图（`script/mod_manager.gd:29-39`）。
- ETN 本体玩家跳跃只改精灵显示高度，没有地形高度查询；`MapBounds` 基于旧场地边界且受信号驱动。阶段 1 可以定义新规则，不把现有行为当作新模式已实现的能力（`script/player.gd:309-320,350-409`；`script/map_bounds.gd:23-51,153-168`）。
- 以下“应交付”是**阶段 1 的文档与示例数据目标**；阶段 2 以后整理运行壳、正式加载器并扩展地形运动、导航及攻击。阶段 0 已有测试入口、读取器、平地移动与表现，不再视为从零实现；原型文件结构也不得自动提升为正式格式。

#### 3.2.1 BSP And Height State / D02 正式决策（2026-11-04，用户确认）

BSP 是二维划分，节点不定义高度；同一个 sector 可有多个 subsector。subsector 只引用 sector 身份，所有高度查询读取该 sector 的当前 `floor_h / ceiling_h`，不在每个叶节点保存独立可变高度。初始值来自 WAD `SECTORS`；活动楼梯/升降台/门仅改变高度时不重建 BSP，但更新显示、接触状态及依赖高度的缓存。

保留 WAD 原始有符号 16 位整数 mu 值（`-32768..32767`），运行时高度、脚底和竖直速度使用 binary64；支持负高度与运动产生的小数，不吸附等级，也不因使用 BSP 而移植 16.16 定点。原始输入范围不自动等于动态状态范围；动态高度/速度范围按 D04 §3.6.1 的地图包络，新格式坐标范围按 D07 §3.12 D07-04/05 随新格式延期，NaN/Inf 必须拒绝。逻辑精度不能经标准 Godot `Vector2/3` 的 float32 往返而静默降低，表现转换放在边界。

区分三种量：D01 的中心点采样地面 `sample_floor_h`；移动查询根据完整占地与开口算出的支撑高度 `support_h` 和可用顶部 `ceiling_limit`；实体当前脚底 `foot_h`。站稳时 `foot_h=support_h`，离地时脚底独立积分；中心仍在低 sector 时，实体可能已由较高台面支撑。地图无地面时不伪造高度 0；§3.15 的无地面出生回退只给玩家初始 `foot_h=0mu`，不改地面查询或伪造支撑。实体碰撞高度 `body_height`、受击高度区间及视觉主体高度分别定义，已验收的视觉 `56mu` 不自动填入前两者。

动态高度与速度范围按 D04 §3.6.1 的地图包络原则；其它实体参数由后续阶段定义。

### 3.3 Step Checks During Movement / D03 移动时实时跨步

D03 已决策。跨步查询见 §3.3.1，接地碰撞响应见 §3.3.3；下列高差判例只说明高度门槛，不能替代完整占地与路径检查。

用户于 2026-11-01 明确：静态楼梯由不同高度的 sector 构成，不设特殊楼梯通行代码；可活动楼梯改变地面的行为不在此结论内。玩家最大向上跨步为 `24mu`，应在尝试移动时用当前状态计算，既不要求显式连接/授权，也不先根据高度差给相邻区域加入“可通行”标签。

在无遮挡、空间足够、仅涉及一个目标台面的简单情况下，向上跨步条件为 `目标地面高度 - 玩家当前脚底高度 <= 24mu`，等于 24 时允许；不能写成绝对高度差，也不能固定比较两个 sector 的静态高度而忽略玩家当前高度。该条件描述跨步高度门槛，完整移动仍需处理实体占地与墙体/竖直空间等条件。DOOM 源码复核支持这一点：本地参考 `E:/DOOMSourceCode/linuxdoom-1.10/p_map.c:189` 的 `PIT_CheckLine` 拒绝单面/阻挡线并收集接触边界的开口；`:399` 的 `P_CheckPosition` 从目标位置 sector 初始化，再按实体包围盒接触的边界修正候选地面/天花板；`:451` 的 `P_TryMove` 检查空间，`:478` 只在 `tmfloorz - thing->z > 24*FRACUNIT` 时因跨步过高而拒绝。跨步判定应随实际体型接近边界触发，不能只等角色中心的 sector ID 改变。

导航可查询几何邻接并在搜索中使用同一移动判定，但不得使派生路径或缓存标签成为玩家移动的授权来源。需要哪些临时派生数据、如何处理不同体型与能力，是阶段 5 的后续设计。

#### 3.3.1 BSP Movement Queries / D03 正式决策（2026-11-04，用户确认）

#### 3.3.3 Collision Response Decision / D03 接地平面碰撞响应正式决策（2026-11-04，用户确认）

**选定方案（user，2026-11-04）**：完整矩形连续扫掠 → 最早接触 → 消除朝障碍内的运动 → 剩余路径继续查询。以下规定普通接地响应；空中、撞顶、落地和失去支撑按 D04，出生初始重叠按 D10，动态平台挤压及实体互推留后续阶段。

1. **停止位置**：推进到本次路径最早阻挡接触的合法位置，保留此前已经完成的合法移动及跨步，不因后半段受阻而退回整帧起点。`32×32mu` 占地先接触就处理，不等中心越线。精确相切允许，朝障碍内部的继续运动禁止。
2. **正撞与斜撞**：普通碰撞不反弹、不自动绕行。正撞时去掉朝内运动；斜撞时只保留合法切向运动，不把投影后变短的位移重新归一化为原长度。单个平直接触的外向单位法线为 `n` 时，剩余位移 `r` 可按 `r' = r - min(dot(r,n),0)*n` 裁剪；离墙方向不裁剪。之后必须重查剩余扫掠，不能把投影直接当作最终合法落点。
3. **速度与手感**：实际平面速度也消除受阻的朝内分量，避免把撞墙速度积存至离墙时释放。输入意图仍保留，下一物理步按原有 `525mu/s`、`1720mu/s²` 基线重新加速；不额外添加碰撞摩擦、沿墙加速或反弹。滑动速度不保证等于无阻挡的满速。
4. **多接触与角点**：同时发生的真实阻挡一起处理。对当前接触形成的平面约束，取满足全部不向内约束、且与原剩余位移最接近的可行位移；凹角没有前进方向时停止，沿墙或离墙仍可行时允许移动。不按 X/Y 固定顺序试走，也不由 linedef/BSP 遍历顺序任选一面。接触法线须来自完整矩形与有限边/端点的实际接触，不能把共顶点但未实际阻挡的所有线都算成约束；越过凸角或离开接触后须释放旧约束并重新查询。
5. **台阶与状态提交**：同一接触时刻先联合检查跨步、净空和整个抬升/平移路径。通过则提交合法的支撑/脚底变化并继续；未通过则把该接触作为当前状态下的横向阻挡并尝试滑动，不先抬高再回滚，不在滑墙时反复获得额外 24mu。滑至新的台阶入口后按新接触重新判断；单个高差只满足高度条件仍不足以放行。
6. **接触余量**：契约按真实边界定义相切与通行，不能以固定外扩代替稳健几何。实现中的数值修正须与坐标精度匹配且有界，不改变 24mu 阈值，不让恰可容纳体型的通道被人为缩窄，不产生可见悬空缝。具体容差在阶段 4 依据边界回归确定，不直接沿用 Godot 默认 `safe_margin` 作为地图规则。
7. **终止与异常**：每轮应消耗剩余路径、完成合法接触状态转换或减少不可行运动；无进展则停在最近合法状态。设置防死循环预算，耗尽时丢弃尚未验证的剩余位移并记录诊断，绝不跳到原目标点；正常多阶楼梯不能因预算过小稳定截断。玩家出生按 D09/D10 不作空间合法性检测，不因初始穿透拒绝进入地图。传送的检查及移动求解中的异常处理按对应机制确定，不借滑动隐式传墙、抬升或选择另一侧落点；运行期移动规则不能反向成为出生加载门槛。
8. **唯一求解所有权**：由模组的地形移动求解器统一算出位置、支撑、脚底与平面速度，现有角色节点承接最终状态与表现。对这条移动路径不再另行调用一次引擎 `move_and_slide()` 重新决定位置。若后续复用引擎查询或加入实体碰撞，也须把结果并入同一提交流程。此项为已选实现路线，尚未修改阶段 0 的已验收代码。

验收要求：正撞/斜撞不可跨的 32mu 台阶；24mu 可跨与大于 24mu 不可跨；高度允许但净空不足；沿阶侧滑至可跨入口；凹角停住/凸角离开不粘连；平行贴墙与反向离墙；恰为 32mu 和略窄于体型的直通道；高速经过薄墙/窄高台；同帧多个合法阶梯；改变候选枚举次序不改变运动结果。以上为正式响应契约及验收范围，不代表功能实现或游戏验收已完成。具体数值容差、防死循环预算与算法实现交阶段 4 通过回归确定；空中/竖直运动按 D04，出生重叠按 D10；动态平台和实体互推由后续对应机制定义。

#### 3.6.1 D04 Items 1–4 / 前四项正式决策（2026-11-05，用户确认）

**来源：user**。用户接受第 1、2 项建议；第 3 项指出强空中控制会改变游戏内容，随后明确选择保留 UZDoom 的 `1/256` 极弱输入推力；第 4 项接受仅接地跨步，但把真实跳跃高度提高为 `36+24=60mu`。以下替代此前待选表；历史分析与旧建议保留在 [移动参考 §7](../../DOOM_MOVEMENT_REFERENCE.md#7-d04-items-14--d04-前四项源码参考与建议2026-11-05)，现行结论见该文 §8。

| 项目 | 选定行为与参数 |
|---|---|
| 1 起跳与竖直运动 | 采用连续时间自由段，真实脚底跳高 **60mu**，恒定重力 **1225mu/s²**，起跳初速取公式 `sqrt(2*1225*60)`，约 **383.405790mu/s**；约 0.312984s 到顶，同高度无障碍滞空约 0.625969s。旧 36mu/296.985mu/s 提案已替代 |
| 2 输入与再跳 | **按住连跳**；真实腾空后的落地统一等待 **0.2s**，包含主动下台；普通接地跨步不触发该计时。无二段跳，松键不截短跳高，不添加离台宽限或离散按键缓存 |
| 3 空中水平控制 | 保留起跳平面速度，空中输入只给 **1/256** 极弱推力；无输入保持惯性，无额外空气摩擦，不自动制动。沿用接地满速 525mu/s 与输入方向映射；以现行接地加速度 1720mu/s² 为基准，空中输入加速度为 **6.71875mu/s²**，反向/横向输入只产生该量级的修正 |
| 4 空中跨步 | **只有实际接地时允许 24mu 跨步**；腾空时不额外抬升，须真实脚底达到台面高度且路径/净空合法。下降接触平台是正常落地，支撑恢复后才重新适用接地跨步。60mu 来自真实跳跃轨迹，不再追加空中 24mu |

竖直自由段使用 `h(t)=h0+v0*t-g*t²/2`、`v_h(t)=v0-g*t`，在真实接触处截断并由同一求解器继续处理；不按每帧固定量改变速度。跳跃顶点自然过零。主动下台沿用经典 DOOM 独立脚底→失去支撑→下坠→落地的思路，保留已接受的静止离台一次性 **-70mu/s** 启动速度，只用于确实失去支撑且原竖直速度为零的离台事件；跳跃顶点、撞顶清零不再次触发。落地贴到真实地面并清除向下速度。第 5 项支撑事件与第 7 项组合接触已由 §3.6.3 正式确定。

空中输入采用推力语义：以逆投影并限制长度不超过 1 的输入方向 `d`，向当前平面速度加 `d*(1720/256)*dt`；首版无外力时保持 525mu/s 的平面速度上限。无输入不调用朝零速度的 `move_toward`；碰撞仍裁剪受阻分量。该数值是把用户选定的 UZDoom 弱推力比例适配到本项目已验收的加速度基线，不声称复刻 UZDoom 全套地面推力/摩擦算术。一次约 0.626s 自由跳中，空中输入累计速度增量的模最多约 4.206mu/s（未计速度上限/碰撞裁剪），正是本次要求的极弱控制。

动态范围沿用已接受的地图包络方案：不另设正常下落终端速度，不把 WAD 16 位高度范围当作动态脚底硬上限。静态地形最高起点 `Fmax`、最低地面 `Fmin` 下，自由跳高度包络为 `Fmax+60mu`，真实 ceiling/体高仍限制轨迹；下落速度按 `sqrt(v0²+2*g*(Fmax-Fmin))` 等能力分支推导并留有界数值余量。非有限值/非法越界保留最近合法状态并诊断，不静默夹高改变玩法；引入平台、外力或传送注入时扩展包络。

**边界验收**：60mu 是无障碍脚底峰值与目标登台高差边界，不表示任意起跳位置/水平时机/平台宽度都能登上 60mu 高台。恰为 60mu 的平台会涉及顶点相切、有限占地支撑及侧碰同刻处理，可达判例已按第 5/7 项在 §3.6.3 确定，运行结果由阶段 4 验证；不能暗加超过 60mu 的跳高、吸附或空中跨步来补偿。落点仍不得跨越无 Sector。

#### 3.6.3 Support And Combined Contacts / 第 5、7 项正式决策（2026-11-05，用户确认）

支撑与组合接触已于 2026-11-05 经用户确认。经典目标占地和 Z 更新仅提供参考（[移动对照](../../DOOM_MOVEMENT_REFERENCE.md) §9），精确相切和同时接触以以下项目规则为准。

**第 5 项选定规则（来源：user）**：

1. 支撑使用 D03 的完整 `32×32mu` 占地及真实地面覆盖；只要仍与当前脚底等高的有效台面有面积重叠，就保持支撑，不要求中心在台上，不设占地比例门槛。只接触竖直台壁不能形成地板支撑；腾空且脚底高于台面时也不能被吸回台面，主动起跳正常解除接地约束。
2. 离开最后一个当前等高支撑后才进入下坠。连续扫掠在实际失去支撑的时刻分段，不在整步起点提前掉落，也不等到下一步才发现。若同高台面连续承接，保持接地；若只剩较低地面，脚底保持原高，在剩余时间内开始下坠，并按 §3.6.1 对符合条件的离台事件仅施加一次 -70mu/s。
3. 精确边/点相切记录为真实接触，结合运动方向处理：已有支撑时可停在精确边缘；继续向外且随后无任何等高支撑时，当场释放，不凭等号或数值余量保留一段悬空时间。向内进入台面时允许建立支撑，沿边保持真实接触时不因枚举顺序抖动。不得扩大台面或加入未选的离台宽限。本规则只针对高低有效地面间的台沿；无 Sector 边缘留给第 6 项。
4. 新落地要求脚底真实到达台面、正在下降或在顶点受重力将下降，且存在可承接的台面接触和合法净空。等号处向台内继续的顶点接触可建立支撑；上升经过台面高度不能被强制落地。多面接触保留完整集合，使用实际首先遇到的合法支撑面，不用中心采样 owner 替代支撑。

**第 7 项选定规则（来源：user）**：

1. 纯落地：令 `foot_h` 到达实际支撑面、向下 `v_h` 清零，落地响应前后 `(v_u,v_v)` 相同；开始既定 0.2s 再跳计时。撞顶只阻断向上速度，并限制头顶不穿越真实 ceiling，后续自然受重力下降；不注入静止离台的 -70mu/s。
2. 同时撞墙/台侧：地板接触处理竖直约束，侧面接触按 D03 去除朝障碍内部的水平分量、保留允许的切向运动。故“落地不改水平速度”不豁免侧碰；不用整向量归零、额外落地减速、反弹或补速。
3. 按真实最早时刻推进，真正同时的有效接触联合约束；不固定用“先落地”或“先撞墙”掩盖另一接触，不将不同时间的事件合为同时。接触后继续求解本步剩余时间，并重新检查支撑与净空；实际支撑恢复后才可使用既定接地 24mu 跨步，不能预判将落地便提前抬高。玩法事件在成功提交时只触发一次。
4. 落地瞬间保留水平速度与后续接地控制分开：剩余接地时间按原接地加速/制动规则演化，不对已经过去的空中时间补算制动，也不额外移植经典摩擦常数。落地后可因惯性继续滑出窄台，再次失去支撑；不把角色锁在落点。
5. 地板与天花板恰好夹住体高时，可同时限制上下运动并保留合法水平运动；净空小于体高则不得作为普通合法落点。动态挤压的伤害/恢复不在本轮新增决定。

**正式验收判例（设计已确定，非运行验证）**：中心已进入低地但占地仍压住高台→不掉落；最后一部分占地移出→从该时刻下坠；同高支撑连续切换→不反复触发落地/离台；纯竖直落地→水平速度无瞬时变化；斜落且撞墙→只裁掉朝墙的分量；撞顶→保留水平速度，除非另有侧碰；窄台落地后继续移出→可以再次下坠。

**60mu 等号正式判例**：连续有地面覆盖、净空足够且没有额外阻挡的情况下，完整占地的前沿在跳跃顶点恰好接触高差 60mu 的台沿，并向台内运动时，允许建立台面支撑并继续登台。脚底低于台面时仍按侧面阻挡；高差超过 60mu 不由本次自由跳直接登上。这里不提高峰值、不做空中跨步、不增加吸附高度；精确顶点相切属于需显式检测的事件，不可只靠每帧采样命中。不是所有起跳距离和水平时机都保证登上 60mu。

#### 3.6.4 One-Sided Boundaries And Broken Maps / 第 6 项单面边界、无效引用与开放轮廓范围（2026-11-05，用户确认）

**现行规则（user，2026-11-12 修正）**：正常单面边界、无效引用、引用有效但轮廓开放是三类问题，分别处理。

1. **正常单面边界**：只有一侧 sector 的 linedef，无论是否设置 `Impassable`，均阻挡玩家全部碰撞体积；接地、跳跃和下坠一致，不按精灵、纹理透明或可见墙高放行。完整 `32×32mu` 占地先接触就停止向内运动，并按 D03 滑动/处理同时约束。“单面”不是单向通行门。例如 WAD x=384 的直边，远离端点时玩家中心最多到 x=368。
2. **支撑边缘区别**：高台与较低有效地面之间允许占地部分伸出台面，按 §3.6.3 保留支撑；不意味着碰撞体可伸到单面线外。D01 边界点有 owner 不等于整个实体可放在该中心。
3. **无效引用**：BSP、linedef、sidedef 等非哨兵引用无效时拒绝加载，定位地图、来源记录及非法目标；不得带病解引用、跳过或自动改写。格式合法的无引用哨兵（如 back sidedef=65535）不当作数组越界，仍须按其所在结构的语义校验。
4. **开放轮廓**：引用有效但真实轮廓开放，若加载阶段能定位异常点，则按一般几何错误拒绝。诊断 sector、端点及关联 linedef；不自动封口、补墙、回位或模拟异常兼容行为。真实边界拓扑检查须排除同 sector 内部线，正确处理内环、不相连分量及多边相接；不要求 subsector 的 seg 列表自行闭合。未可靠定位的异常不假称已检出，不承诺识别所有错误 WAD。

### 3.8 D06 Sky Attack State / D06 攻击遇天空后的特殊状态正式决策（2026-11-06）

**已决策（user，2026-11-06；计时参数于 2026-11-11 确认）**：承接 D05 天空分类，以下是后续攻击接入须遵守的状态语义；不要求阶段 1 创建弹射物实体。

| 攻击类型 | 首次命中天空 Linedef 部分或天空 Ceiling | 此后的行为 |
|---|---|---|
| 弹射物 | 立即赋予特殊状态，启动该状态的计时器 | 不再发生碰撞，保持飞行；计时器结束后删除 |
| hitscan | 从该天空命中点起进入不再碰撞的后续段 | 后续一直延伸到该次 hitscan 最大距离 |

**弹射物语义**：两种天空面使用同一状态转换。首次触发时不删除、不触发撞击爆炸；转换后不再因墙面、地板、Ceiling 或实体产生碰撞响应/碰撞命中，包括后来重新进入普通区域。计时器属于该状态，从首次进入时启动，不能因经过其它天空面重复刷新；到期删除不改成一次撞击爆炸。“保持飞行”保留飞行表现，不在此擅自新增弹道、加速度或制导规则，具体运动模型归 D06 对应武器。

**hitscan 语义**：天空之前仍按正常规则判断命中；一旦先命中天空部分，后续地形/实体不再截断该次射线，也不再产生碰撞命中。最大距离沿用本次发射的总射程，从发射起点计算；不是从天空命中点重获一段完整射程。不能仅隐藏命中特效而仍让后方实体受到这条射线的命中。

**判例**：两侧 sky Ceiling 分别为 128mu/64mu，弹射物在 96mu 高度水平穿过其上部高差天空墙面时，立即进入特殊状态；此后处在较低 Ceiling 上方也不触发再次碰撞或立即删除，继续飞行至计时到期。先遇普通墙或普通实体的攻击仍按正常命中规则处理；仅一侧 sky 的上墙面及单面边界不触发天空状态。hitscan 先遇天空后，即使剩余射程内存在普通墙或目标，也延伸至原最大距离且不再命中它们。

计时与清理统一见 D06-13：默认 2.0 秒游戏模拟时间、类型可覆盖、暂停停表、天空计时接管普通寿命/射程清理，卸载立即回收。

#### D06-01 Cursor Surface / 鼠标选择什么表面

**已决策（user，2026-11-11）**：参考 isodoom。

- **选定规则**：采用 §3.4 的地面拾取语义：相机射线选择最近的实际地面交点，忽略墙面、天花板与角色精灵；覆盖和边界归属消费 D01，不将 BSP 候选直接认作地面。保留地面高度与是否命中地面的标记。

#### D06-02 Cursor Fallback / 无命中、零方向与准星反馈

**已决策（user，2026-11-11）**。

- **选定规则**：无地面命中时与玩家当前 `foot_h` 平面求交，标记为非地面兜底点。兜底也失败或平面方向长度为零时，保留上一有效朝向，尚无历史值则用出生朝向；不伪造地面/目标。UI 消费鼠标的输入优先于开火。屏幕准星跟随鼠标；辅助目标只在成功选中时另给轻量标记，不把准星吸到目标上。

#### D06-03 Vertical Aim / 垂直瞄准与辅助目标选择

**已决策（user，2026-11-11）**：选定 ±45° 初值。阶段 1 不引入敌对实体，目标选择/辅助俯仰的实战验证留后续；缺少实战验证不等于设计未决。下文有限体积弹道条件是后续能力接入时的要求，不代表 D06-07 的体积/弹道方案已被采纳。

**选定规则**：

1. **范围**：使用面向逻辑平面准星方向的有限三维攻击体积：水平胶囊向上挤出为具有独立高度范围的体积，随真实脚底移动；不直接复用投影后的 `Area2D` 或精灵姿态条件。继承 ETN 短窗口、多目标的方式；0.1 秒窗口与 0.2 秒冷却可作为后续调参参考，不在本轮批准为 ETNDOOM 参数。水平尺寸、前伸与竖直范围在近战样例阶段标定，不把 ETN 二维单位直接认作 mu。

3. **有效接触**：每次收集候选时检查攻击体积与受击体的真实三维相交，并从攻击锚点向相交区域中的候选接触点检查地形遮挡；用候选区域内的最近点作为初版规则。高度不相交或连接线被地形截断就不登记；仅有移动阻挡 flag 或 middle texture 不擅自新增攻击阻挡。天空终止可伤害路径，不将天空后的目标加入命中集合。候选点被遮挡但局部另有可达点时，最近点方案可能漏判，作为初版简化明确验收。
4. **时机与去重**：在窗口内首次有效接触时立即提交一次伤害，并按“本次攻击 ID + 实体 ID”去重；多个 HurtBox 不重复打同一实体。窗口开始即检查已有重叠，不只等 `area_entered`。这有意改变 ETN“窗口结束才批量提交”的延迟：碰到即有反馈，离开后不补一笔迟到伤害，也不在结束时撤销已有效命中。动画/声音须与这一命中时机同步。
5. **阶段边界**：本阶段仅裁定采用方向和地形/高度接口；体积参数、伤害、击退、暴击、特殊角色派生、敌对实体接入和实战测试留后续。不因确认玩家近战而提前引入敌人。

**理由与判例**：玩家保留 ETN 扫到多个近处目标的手感，墙体和高台仍提供真实保护；隔墙重叠不命中，攻击高度与目标无交集不命中，同一实体多个 HurtBox 至多一次。具体敌人规则后续裁定。

#### D07-01 Data Layers / 原始地图、查询几何与表现分层

保留经典 WAD 原始拓扑和预存 BSP，加载时派生统一查询地面片，再生成表现几何；首版不要求地图作者另行维护地面多边形文件。“统一定义”首先是内存数据约定，不强制引入独立序列化格式。

| 层次 | 数据与职责 |
|---|---|
| 原始地图层 | 保留 `VERTEXES / LINEDEFS / SIDEDEFS / SECTORS / NODES / SEGS / SSECTORS` 及原始记录索引，作为地图定义与错误追溯依据 |
| 查询几何层 | 有效地面片、sector/subsector 关联、边界来源、几何邻接与辅助包围盒，供覆盖、运动、射线及后续导航共同消费 |
| 表现层 | 从同一地形定义生成地板、天花板、墙面网格及材质，不以渲染网格或三角形编号反向定义玩法区域 |

允许加载时建立引用、裁切地面片、三角化，不改变原始 BSP 分割线、树结构和 child 顺序，不增加 BSP 构建器或第二棵渲染 BSP。后续视线消费者另阶段裁定，不借本项恢复 D06-12。

#### D07-02 Coverage Pieces / subsector 关联的有效覆盖

每个 subsector 关联其有效覆盖几何，每个地面片引用所属 sector；一个 sector 的整体覆盖由相关地面片共同表达。允许内环、不相连区域和必要分片，不强制一个 sector 对应一个简单多边形，也不要求经典 subsector 的 seg 列表自行闭合。

查询几何至少保留下列语义；代码字段名与 Godot 类型不在此冻结：

| 信息 | 来源或关系 | 约束 |
|---|---|---|
| 有序边界及必要分片关系 | 已有 BSP 约束与真实地图边界 | 保留实际覆盖、内环和不相连分量，不取凸包补面 |
| 所属 sector | 经 seg / sidedef 关联并校验 | 引用同一 sector 的高度与素材定义，不独立复制可变高度 |
| 来源 subsector | 原始 `SSECTORS` 索引 | 与已有 BSP 定位关联，不充当持久地图身份 |
| 边界来源 | 原始 linedef、对应侧或派生切分关系 | 可区分真实边界和内部切缝，保留诊断关联 |
| 辅助包围盒 | 从有效几何派生 | 只作筛选/计算域，不定义地面 |
| 原始记录关联 | node / subsector / seg / linedef 等索引 | 构建或一致性错误可追溯到输入 |

按 D01 §3.1.10 沿已有树的分割约束建立候选片，并结合真实边界核对覆盖；初始化裁切的矩形残留不能成为地面。三角化仅为派生处理，不改动 owner 和真实接触语义。具体算法留阶段 3 实现，须覆盖斜边、内环、不相连分量、共享顶点及地图外部判例。

#### D07-03 Edge Provenance / 真实线与内部切分边

真实 linedef 的派生边段保留原始 linedef 索引和对应侧；仅由 BSP 裁切或三角化生成的边标为内部切分边。同一 linedef 的多个 seg/边段仍可追溯并按原始线去重。内部切缝不产生墙、不触发跨步，不随渲染三角形改变地形归属。

完整保留原始 linedef 表，不只保留地面片外轮廓；同 sector 内部的合法阻挡线仍按 D05 参与检查。无需为此引入 GL nodes，且不得把没有真实 linedef 的切分边当作新增障碍。

#### D07-04 Sector Heights And Precision / sector 高度与数值

原始 sector 保存初始 floor/ceiling 高度；运行时 sector 状态统一持有当前高度，subsector、地面片及墙面/开口计算引用它，不维护独立可变高度副本。仅高度变化不重建二维 BSP 或平面覆盖，须刷新依赖高度的显示、开口及其它缓存；此一致性要求不增加本阶段的门/升降台玩法。

经典 WAD 顶点坐标及 sector 高度按原始有符号 16 位整数 mu（`-32768..32767`）无损保留；运行时计算使用 binary64 并遵守 D01 稳健几何谓词要求，派生交点不取整、不吸附网格、不经 float32 表现向量回写逻辑真值。运行状态范围仍按 D02/D04，输入范围不强加给动态状态。无地面不伪造 `0mu`；实体脚底、支撑和鼠标状态不写入静态地图。新格式的小数输入及扩展坐标范围随新格式延期，不限制运行时产生小数。

#### D07-07 Validation And Diagnostics / 加载校验与原始记录诊断

2. 引用：检查顶点、linedef、sidedef、sector、seg、subsector、node 关系；合法无引用哨兵按语义处理，不能当作越界目标。

### 4.2 Shared Queries / 共享查询输入、输出与失败语义

以下名称描述信息含义，沿用既有符号，不新增强制序列化字段或错误码。查询只读几何/当前高度并返回结果；唯一移动求解器或正式攻击提交者负责状态及副作用。

| 查询 / 依据 | 输入 | 结果与边界 |
|---|---|---|
| 地面点查询 / D01–D02 | 有效逻辑 `(u,v)`、已校验覆盖与 BSP、sector 当前高度 | 有地面时返回唯一 `owner_sector` / `floor_h`；返回 `on_boundary`、完整 `touching_sectors` / `boundary_ids` / `touches_void`。严格无覆盖返回无地面且不造高度；非法输入/地图损坏是错误，不能混为无地面 |
| 移动与接触查询 / D03 | 完整占地、当前位置/脚底/支撑与速度、体高/能力、尝试路径和时间段 | 返回实际最早接触、同时约束及来源、候选 `F/C` 和受阻原因；求解器按跨步/净空/滑动规则推进剩余路径，统一提交位置、支撑、脚底和速度；试算不触发玩法 |
| 支撑与落地查询 / D04 | 完整占地及连续运动、`foot_h` / `v_h`、当前支撑、有效 floor/ceiling | 返回保持/失去支撑、实际落地/撞顶接触及同刻侧碰约束；在真实事件时刻转换，不用中心 owner 替代支撑，不凭终点忽略无 Sector 路径 |
| 地形射线 / D05、D06-06/14 | 逻辑三维起点、方向和总射程，真实墙面及覆盖内 floor/ceiling | 返回最早事件的距离/位置、表面类别及来源；真正同刻普通阻挡地形优先于天空，实体接入后再按既定顺序处理。未命中与查询错误区分；天空后的无碰撞段由攻击语义处理 |
| 鼠标拾取 / D06-01/02 | 相机射线、有效地面、玩家当前 `foot_h`，朝向兜底所需历史/出生朝向 | 最近真实地面点及地面标记；无命中转脚底高度平面并标记非地面；失败或零方向保留有效朝向/出生朝向。忽略墙面，不复用攻击阻挡结果 |
| 玩家出生初始化 / D09–D10 | 选定 type 1 的位置/angle、32×32mu 占地、56mu 体高、D01 结果与实际双面开口 | 有覆盖时计算 `F/C` 后抬高/撞顶下压；中心无覆盖则告警且仅令 `foot_h=0mu`。保留原始索引和诊断，不返回“出生合法”承诺，不伪造支撑或最近合法状态 |

**一致性约束**：

- `sample_floor_h`、候选 `F/C`、有效 `support_h`、实体 `foot_h` 各司其职；出生下压不回写地形或证明支撑有效。普通移动净空不足会受阻，出生净空不足仍按 D10 初始化，不能把两者合并成同一准入检查。
- 地形来源可追溯到地图及原始 sector/linedef/seg/subsector 等记录；一个真实 linedef 的多个 seg 去重，内部切缝不成为障碍。subsector 仅为查询关联，不是稳定地图身份。
- 无地面、无命中、受阻、非法输入/损坏数据须分别表达。受阻原因按实际接触指出单面边界、适用 flag、高差或净空等；诊断不能以默认 owner、默认 0 或空结果掩盖错误。
- 几何试算无拾取、伤害、声音或跨线副作用，导航可重复调用同一移动规则；实际事件仅在正式提交时按既定顺序生效。D06-12 视线不纳入本表。
