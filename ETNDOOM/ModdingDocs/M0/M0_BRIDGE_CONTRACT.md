## 1. Layers / 两层接口和版本

> Revision / 修订（2026-11-16，来源：user）：[迁移裁定](M0_LEGACY_MIGRATION.md) §2.1、§3 已确认原规则基线与 M0 获准 WAD 限制。D08 的通用资源/身份/ETNINFO 契约为 B2/M3；本文的必要会话代次与验证证据身份不等于恢复旧 D08 资源能力门槛。完整资源操作面仅作后续设计，M0 不以实现通用 PWAD 装载为通过条件。俯视输入/表现边界归 B1/M2，功能本身不属于 M0。

首版围绕已选定的 Crispy Doom 设计直接、够用的 Godot 接入。内核持有模拟状态，宿主读取状态并提交输入；接口可以使用 Crispy 特有字段和调用，不要求先建立端口无关的公共 ABI 或通用适配器框架。C/C++ 内部可按需复用原生类型；跨 DLL/Godot 边界仍须明确类型、所有权和寿命，不能把裸指针当作可跨会话保存的身份。

| 层面 | M0 必须固定 |
|---|---|
| 内核 ABI | 版本、结构大小/字段宽度/符号、调用约定、对齐、所有权、错误返回、支持的操作集合 |
| Godot API | 扩展类注册时序、方法/数据格式、失败时脚本可用性、主线程调用约束 |
| 内容与规则 | 内核 commit、补丁身份、资源集身份、兼容配置身份、存档 schema |

版本或必需能力不匹配时在建会话前拒绝，不猜测结构。若使用二进制序列化，固定字节序与长度；若用 Godot 容器，规定 64 位 ID 的无损表示，不能经过浮点数/不保真 JSON 消费端。

### 1.1 Backends / 多端口边界建议

> Revision / 修订（2026-11-16，来源：user）：首个内核确认为 Crispy Doom。目标端口数量有限，甚至可能只有 Crispy 与 GZDoom/UZDoom；现代端口也存在相互模仿与兼容，因此不必严格要求完全公共桥接接口或每端口通用适配器。SUPERSEDED: 此前要求首版预建公共 ABI、统一能力模型与独立通用适配器的建议。

- 先让 Crispy 在 ETN 中完整运行；接口按 M0–M1 的真实调用和 M2 的明确消费需要形成，允许端口专用字段、直接包装及少量条件分支。
- 接入 GZDoom/UZDoom 时再依据实际差异选择复用、局部改造或必要抽象，不提前实现后端注册系统、完整能力协商或覆盖所有端口的数据模型。现有构建/配置身份足以表达来源时，无须另造公共机制。
- 保留必要的工程边界：模拟唯一真值、输入/tic、状态读取、内存寿命、错误、会话清理和存档所属版本。这些为当前宿主集成所需，不因减少通用化而取消。
- 最终切换目标不变；具体切换粒度及存档互通尚未裁定。上游端口间的兼容可以按实情复用，但不据此预先宣称存档、运行状态或内部对象布局互通。

## 2. Operations / 最小操作面

| 操作概念 | 输入 | 输出/约束 | 阶段 |
|---|---|---|---|
| `get_build_info` | 无 | ABI、内核/构建/依赖身份、能力、数值/tic 描述 | M0 探针 |
| `create_session` | 资源清单、游戏/兼容配置 | 会话身份或错误；初版拒绝第二个活动会话 | M0 探针 |
| `start_game` | 起始图/episode、难度等 | 执行内核新游戏流程，提供第一份有效地图与快照 | M0 探针 |
| `submit_commands` | 带 tic 的命令批次 | 接受范围与错误；不直接改位置/生命值 | M0 探针 |
| `step` | 待执行整数 tic 数 | 实际执行范围、状态、快照/事件位置 | M0 探针 |
| `read_map` | 会话/地图代次 | 静态拓扑、材质引用与地图元数据 | M0 最小字段；M1 完整 |
| `read_snapshot` | 当前会话/帧身份 | 完整快照；增量是后续可选优化 | M0 最小字段；M1 完整 |
| `read_events` | 最后确认的事件序号 | 顺序批次与溢出状态；确认后才可回收 | M0 最小事件；M1 完整 |
| `read_resource` | 解析后的资源句柄 | 受长度限制的数据、类型与解码/格式信息 | M0 定义；M1 实现 |
| `set_paused` | 明确暂停/恢复 | 新状态；恢复不补暂停期间 wall time | M0 探针 |
| `request_flow_action` | 合法的结算确认/重开等 | 由内核状态机处理；不能直接指定“假已过关” | M0 定义；M1 实现 |
| `save_game` / `load_game` | 独立槽位、预期身份/数据 | 完成/错误；恢复后触发全量重建 | M0 审计；M1 实现/验收 |
| `destroy_session` | 当前会话身份 | 释放结果；旧命令、句柄和快照失效 | M0 探针 |

上表不要求 M0 实现完整接口。最小可行性探针不能用常量坐标/假 tic 代替真实内核调用；M1 开始前完整操作面的语义和归属必须确定。

## 3. Lifecycle / 生命周期与状态机

建议桥接状态为 `READY → SESSION_CREATED → RUNNING ↔ PAUSED → DESTROYING → READY`，可恢复初始化失败回到 `READY`；污染会话的错误进入 `FAILED`，只允许诊断/销毁。内核另有 `level/intermission/finale` 等实际状态，两者分开记录。

操作合法性必须有表：无会话不能步进；暂停时不消耗玩法 tic，但 UI/退出命令仍可处理；换图/读档在 tic 边界串行执行；销毁后重复请求不触碰已释放内存。禁止在取快照/音频回调中重入 `step` 或销毁。

出生、换图、重开、读档与传送分别定义：前三类通常重建地图/实体，读档即使回到同图也建立新的世界代次；传送只使相关实体跳变。具体内核行为应保留，表现端据明确标记断开插值。

## 4. Time and Commands / 固定步进与输入

### 4.1 Clock / 谁控制时间

建议由桥接唯一负责 wall time → 整数 tic：经典目标为 35 tic/s，调用实际完整游戏调度；上游主循环/SDL 时间服务不得再额外推进第二套时钟。显示帧率可高于模拟频率，`Engine.time_scale` 和 Godot 物理频率不得隐式改变 DOOM 规则。

M0 冻结如下行为：

- 确定性对照直接执行指定数量 tic，不读取实时帧率。
- 实时模式每帧补 tic 有预算；未完成的欠账显式保留，记录积压。达到阈值时采用已定义的降速/暂停/报错策略，不静默跳过 gameplay tic 或放大 `dt`。
- 暂停期间不增加模拟欠账；恢复/失焦策略显式记录，按键释放状态清理。建议首版单人失焦暂停；最终由 M0-D07 冻结。
- 命令按目标 tic 消费；一次按钮按下是否形成连续 fire/use 由上游语义决定，不能所有按钮一律边沿化。菜单确认/暂停等宿主动作另行定义。

每帧最大补 tic、最大积压、输入队列长度和暂停策略是必须填写的参数；根据 P3/P4 测量确定，不能空缺进入 M1，也不在未测量时宣称预算已达标。

### 4.2 Command / 输入字段与量化

每条命令至少包含：`session_epoch、world_epoch、target_tic、player_slot、sequence、forward_move、side_move、angle_turn、buttons/weapon_request`。字段宽度、范围、饱和与舍入按选定内核 `ticcmd` 固定；超界、重复、迟到和跨代次命令均有可观察处理，不静默重排或重放。

已选 Crispy Doom 原生支持可选跳跃，按其命令字段/配置接入并验证；已有源码证据见选型 §8.3。不得以旧 ETN 跳跃算法替换。跳跃姿态、光环滞后、起跳烟尘及音效始终为 B2/M3；实际 ETN 接入尚未完成。

测试回放必须为每 tic 提供明确命令；实时模式缺样本时按冻结规则生成命令（例如连续轴保持、离散请求清空），不能让“没读到输入”随机变成重复开火/菜单确认。一次显示帧补多个 tic 时也必须定义命令分配方式。

俯视输入链：屏幕方向 → 世界方向 → 根据当前朝向投影成前进/横移命令 → 量化/饱和；鼠标目标生成转向命令，不直接写 actor 朝向或位置绕过内核入口。既有 `coordinates.gd:22` 把方向乘 `525.0`，只能复用方向变换思路，不能把速度常量带入原规则基线。

至少核对东/北/西/南朝向、屏幕四向、斜向、转向跨零、零输入及按住/释放；Godot 鼠标射线只负责选择目标。命中/自动瞄准仍由内核处理，三维自由瞄准另见 D06 迁移。

## 5. Coordinates and Identity / 坐标、精度与身份

表现链保持：WAD/内核 `(x,y,z)` → 逻辑 `(x,-y,z)` → Godot `(x,z,-y)`，高度为脚底 z。`etndoom_mod/stage03/coordinates.gd:7,10` 是逻辑到 Godot 的既有入口；原点偏移如引入，必须作为地图级字段只应用一次。

内核原始定点/角度用于差分，不经 `Vector2/3` float32 回写。接口需同时说明原始表示与显示值；量化误差仅容许在表现，不以视觉容差掩盖模拟分歧。朝向规定零点、正方向、范围及 billboard 帧选择，不只验证坐标。

| 身份 | 建议语义 |
|---|---|
| `session_epoch` | 每次建会话递增，进程内不复用；不是永久存档 ID |
| `world_epoch` | 换图/重开/读档重建时更新；同名地图也不能沿用旧引用 |
| `tic` / `snapshot_seq` | 区分内核可随读档回退的游戏 tic 与桥接单调递增输出序号 |
| `entity_id` | 对象寿命内稳定，当前世界内不复用；允许代次+槽位形式，严禁裸指针代替 |
| `sector_id/line_id/side_id` | 与本次地图装载结果绑定；导出顺序明确，不假设重载后仍可引用 |
| `resource_handle` | 绑定资源集/代次，覆盖或会话重建后按契约失效 |
| `resource_set_id` | 对有序文件内容、补丁与解析所需选项形成稳定身份；路径仅用于定位，不决定相同内容是否等价 |

参考构建与端口不比较指针。若实体 ID 为观察工具附加，需用明确的创建序号/映射匹配，不改变内核 thinker 次序。

## 6. Data Surface / M2 需要的数据面

| 数据块 | 最小语义字段 | 更新方式 |
|---|---|---|
| 静态地图 | 地图标识/代次、顶点、line/side/sector 关系、方向、flags/special/tag、贴图与偏移、可用空间/绘制拓扑 | 装图时全量；BSP/seg 若导出需保留关联与真实边来源 |
| sector/side 状态 | floor/ceiling 高度与材质、light、sky 标记、贴图动画/平移或开关变化、内核存在的扩展字段 | 每 tic 全量或带基线的增量；不由 Godot 重算机关 |
| 实体 | ID、类型/状态、位置/动量、角度、sprite/frame/朝向信息、可见/死亡等表现标记、必要的尺寸 | 批量快照；生成/删除由快照或事件明确定义 |
| 玩家/HUD | 对应实体、生命/护甲、弹药、武器/切换、钥匙、powerup、伤害/拾取反馈、难度 | 读取真实状态，不由动画推断 |
| 游戏流程 | 实际 gameaction/gamestate、当前/下一图、统计、秘密出口、结算/结束阶段与合法操作 | 状态变更+全量快照可重建 |
| 资源 | 最终解析后的纹理/flat/sprite/调色板/声音/音乐信息，原始逻辑尺寸与表现尺寸分离 | 句柄按资源集有效，显示缓存不改变解析顺序 |
| 诊断 | 输入消费 tic、步进数、事件范围、溢出/错误、计时与内存计数 | 诊断开关不改变玩法或 RNG |

M0 要在选定版本上给出真实字段来源、可导出性与一份示例。这里列的是语义需求，不要求将全部内存结构原样暴露。首版未支持的扩展字段显式标记，不返回貌似有效的零值。

地图表现不能只接一个“玩家 x/y”接口后再临时读取内核私有对象。若现有 mesh 算法仍读取 WAD，必须使用同一内核已确定的有效资源/地图数据与身份；不得让两套加载器各自选择覆盖结果。

## 7. Snapshots and Events / 快照、事件与插值

初版优先每 tic 批量完整快照，按测量决定是否引入增量。完整快照用于重同步；增量需 `base_snapshot_seq`，缺基线时申请全量，不能继续猜测状态。

事件头至少为：`session_epoch/world_epoch/tic/event_seq/type/entity_id（可选）/payload`。快照是状态，事件是一次性发生的反馈；生命值归快照，声音开始/停止、一次性反馈与流程通知按序号消费。即使快照可补回生命值，也不能用它推断完整声音序列。

- 一个显示帧补多个 tic 时，所有关键事件都须保留；不能只保留最终快照时刻的事件。
- 事件队列满时报告明确状态，停止继续产生不可恢复丢失或执行约定的重同步；不得静默覆盖未确认事件。哪些纯视觉事件允许合并需逐类声明。
- 消费端按序号确认/去重；退出、换世界、读档清理旧声音与反馈，不重放旧队列。
- 插值只在同一实体、同一世界的连续快照间进行；生成/删除、传送/读档/换图跳变标记打断。插值不影响碰撞或命中。
- 音频回调线程若存在，只读已提交数据，不触发 Godot 场景树访问或重入模拟。音乐解码/播放方案单独列依赖和授权。

## 8. Memory and Errors / 所有权、线程与错误

M0 必须选择明确的缓冲策略，例如内核拥有只读缓冲至下一次变更调用、桥接在调用返回前复制到 Godot 自有数组；或调用方提供容量并返回所需长度。无论选哪种，都定义释放方、失效时点、容量上限与不足时行为，不能跨 CRT 任意 `free`。

默认所有模拟/取状态/销毁在同一宿主主线程串行进行，禁止重入。初版不以工作线程掩盖卡顿；后续线程化需重新定义快照发布、暂停、退出等待与锁。

| 错误类 | 返回/状态要求 |
|---|---|
| 参数/身份错误 | 不改状态，返回类型、操作、预期/实际值 |
| 文件缺失/路径/格式可恢复错误 | 给出文件、lump/偏移（若可定位）、失败阶段；释放部分资源，回到可操作状态 |
| ABI/依赖/扩展加载失败 | 不创建会话，不解析必须依赖原生类型的后续脚本；保留菜单与诊断 |
| 初始化/装图中断 | 明确旧会话是否仍有效；不得部分新世界继续步进 |
| 原生内部致命错误 | 明确会话不可继续；审计上游 `I_Error/exit/abort`，不能让常规输入错误直接终止宿主 |
| 进程崩溃/访问违规 | 记为探针失败，由外部监督记录；不承诺普通返回值可恢复任意内存破坏 |

错误跨 C ABI 不抛异常；C++ 回调边界捕获范围、内核错误机制及清理策略按候选实情实现。不能用跨越任意 C++ 栈对象的非局部跳转作为未经审计的恢复方案。

## 9. Save Identity / 存档与规则身份

建议保留上游实际存档载荷，在外部封套记录：schema、内核/补丁身份、资源集与加载顺序身份、兼容配置、游戏模式/地图、规则扩展版本。绝对路径仅作重新定位提示，不是文件相同的判据。

初版建议严格匹配兼容身份；不匹配先拒绝或要求明确迁移方案，不直接强行载入。上游 savegame/demo 格式兼容分别声明，不因继承归档代码就承诺所有历史存档可读。

存档在 tic 边界生成；写入临时文件再提交，失败保留旧槽位。读档后世界代次更新、全量重建表现与声音，恢复 RNG、玩家、thinkers、specials 等实际载荷。M0 定义字段与审核调用链，M1 对照运行验证；存档不能只保存 Godot 快照。

**固定源码审计（2026-11-17）**：Crispy `G_DoLoadGame` 经 `G_InitNew` 清 RNG，`p_extsaveg.c` 的扩展表没有三组 RNG 索引，故“保留上游载荷”本身不足以保证精确续跑。M1 须审计并补齐独立封套中的 RNG/调度状态，以“未中断”对照“保存→读取→继续命令”验证，详见 [M0_SOURCE_AUDIT.md](M0_SOURCE_AUDIT.md) §3；本条不声明 M0 已实现存读档 API。

## 11. Implemented v0 / M0 实际接口冻结（2026-11-17）

Source / 来源：code；行为验证结果见[探针记录](M0_PROBES_AND_ACCEPTANCE.md)。Godot 扩展类为 `CrispyDoomBridge : RefCounted`，消费者为 `etndoom_mod/m0/session.gd`；C ABI 版本为 1，声明在 `native/m0_core.h`。桥接不使用 `godot-cpp`，直接使用 Godot 4.7.2 导出的 C GDExtension 接口头与函数地址。实际发布版引擎身份以 P0/P2 为准，`.gdextension` 的 minimum=4.2 只是所用接口的最低声明，不等于已经测试所有 4.2+ 版本。

| 操作 | 当前入口 | 实际含义与未实现边界 |
|---|---|---|
| 构建身份 | `build_info()` → `build_info_json()` → `m0_build_info()` | 内核 commit、ABI、ticrate、定点位数、软件渲染、audio/network=false；桥接补实际 DLL 编译 `bridge_build`。创建前检 ABI，不仅查导出符号 |
| 创建/开始 | `create_session(resource, jump)` / `open` → `open_core` → `m0_create` | `fixture` 或 `doom2`，固定获准绝对路径；episode=1、map=1、命令行 skill=3（内核枚举值 2）。创建即完成新游戏和装图，无第二套 start API |
| 输入/步进 | `submit_commands`、`step`、`command` → `step_core` → `m0_step` | 明确命令队列；逐 tic `M_Ticker→RunTic→G_Ticker`；不调用 Godot 物理求解器、不由显示额外推进 |
| 静态图 | `map_data()` → `map_json()` → `m0_map()` | `vertices` 为定点 `[x,y]`；`lines` 为 `[v1,v2,flags,special,tag,side0,side1]`；`sides` 为 `[sector,textureoffset,rowoffset,toptexture,bottomtexture,midtexture]`；`sectors` 为 `[floor,ceiling,floorpic,ceilingpic,light,special,tag]`，索引来自内核装图顺序 |
| 快照 | `snapshot()` → `snapshot_json()` → `m0_snapshot()` | 真实 tic/leveltime/gamestate/gameaction/map/episode/skill、3 RNG 索引、实体数量、玩家、sector 动态值；完整实体列表/稳定 ID 属 M1，无伪造占位 |
| 帧缓冲 | `dimensions()`、`framebuffer()` → `m0_frame` | 320×200 RGBA8，256000 字节；Godot 自有 `PackedByteArray`，内核出错返回空数组；原生容量不足返回所需字节数且不越界写 |
| 暂停/事件 | `set_paused`、`read_events`、`acknowledge_events` | 宿主停止消费 gameplay tic；事件仅生命周期，非完整声音/玩法事件 |
| 销毁 | `close()` → `close_core()` → `m0_destroy` + `FreeLibrary` | 释放内核登记堆/文件和 SDL 后卸载内核 DLL；扩展类继续驻留；重复 close 幂等 |
| 资源/流程/存档 | 尚未提供公开 API | M1 按 §2、§6、§9 和源码审计补实现，M0 不返回虚假成功或模拟字段 |

命令使用 Godot 64 位整数承载身份/序号，原生五个控制量转换前校验 int32；`forward_move/side_move ∈ [-50,50]`、`angle_turn ∈ [-32768,32767]`、`buttons ∈ [0,127]`、`arti ∈ {0,128}`，`player_slot=0`。按原生 `ticcmd` 打包，不经 JSON 浮点传递命令。序号必须严格增加、目标 tic 连续，旧代次、重复/倒退、缺字段、范围错误整批拒绝；队列容量 1024，缺命令则拒绝 step。实时连轴按键在每个补 tic 采样为同一保持值，武器切换只注入一次，fire/use 保留上游按钮语义。

会话/世界计数在 Session 脚本内以 static 单调分配；当前世界 map 改变或 leveltime 回落更新世界代次、清旧队列并提前结束批次。退出销毁使旧引用失效；完整读档/同图重建的显式 world generation 在 M1 公共流程入口中接入，不能把当前观测规则当完整存档恢复证明。快照另附 `session_epoch/world_epoch/next_tic/snapshot_seq`。当前 C JSON 中的原始位置为 int32，角度为 uint32，计数在 M0 运行范围内可被 Godot JSON 精确表示；持久 64 位 ID 不加入此 JSON 路径。

事件上限 256，头含 `session_epoch/world_epoch/tic/event_seq/type/payload`；当前类型为 `session_started/world_changed/paused/resumed`。`read_events(after_seq)` 不删除，`acknowledge_events(seq)` 后回收，消费者去重；满队列拒绝继续推进/暂停变化，不覆盖旧事件。快照 C 缓冲上限 1 MiB，地图 4 MiB，溢出明确返回 `SNAPSHOT_CAPACITY/MAP_CAPACITY`。C 静态字符缓冲由内核持有，桥接返回 Godot String 前复制；Godot 数组/字典再深拷贝，不保存原生指针。

当前地图/实体/事件真实样例来自获准自制图初态：玩家 `x=-8388608,y=0,z=0`，即 `(-128,0,0)mu`；`angle=0` 表示 +X，`0x40000000` 为 90°；玩家 `health=100,armor=0,weapon=1,state=0`，`entity_count=1`；首 sector 动态值 `[0,16777216,192,1,54]`（floor=0、ceiling=256mu）；首事件为 `session_started`，payload=`{resource:"fixture",jump:false}`。完整静态数组和逐 tic 快照保存于本地 P3 结果，不能将该单实体样例推广为完整实体 API。

实时预算冻结：35 tic/s；每帧最多 8 tic；70 tic 欠账警告；超过 350 tic 进入需重开/返回的暂停状态并保留欠账。普通暂停/失焦不累计 wall time，清输入和一次性请求；超限不会静默删除欠账继续运行。性能指标由 P3 实测填写，不将 28.57ms 模拟间隔当作可全部耗用的最终帧预算。

错误以 `{ok:false,stage,error}` 或原生明确诊断返回。文件缺失/参数错误在建会话前拒绝；核心可恢复错误只在 C `setjmp` 保护栈内返回，不越过 C++ 析构对象；保护外内部编程错误仍不可恢复，不承诺任意内存破坏可返回菜单。FAILED 会话只允许诊断和关闭；下一次加载全新内核 DLL。完整错误目录及源码身份由构建锁与探针逐项记录。
