## 3. Reference / 独立参考与比较规则

继续使用单独编译的 Crispy 参考程序：保留上游主循环与命令调度，注入冻结 tic 输入并只读观察；不能调用待测核心的 `m0_step` 生成期望。共享只读序列化可沿用，但关键断言另核对原生字段/流程结果，避免序列化共同漏字段导致假通过。

两端锁定 commit、补丁身份、资源内容与顺序、skill、起始图、jump/其它选项、初态 RNG、音频逻辑模式、擦屏/显示配置和每 tic 输入。存档封套的正确性以**未中断路径**作主要参考，不让参考端复用待测封套恢复实现后互相比对。

| 比较类别 | 规则 |
|---|---|
| 模拟整数 | 位置/动量/角度、生命/弹药/武器、RNG、state/tics、sector/side、specials 与流程精确比较 |
| 实体身份 | 禁比较地址；按明确的创建/归档映射规范化 observer ID，保留引用图与 thinker 次序差异 |
| 事件 | 规范化 session/world/输出序号，比较语义类型、对象关系、payload、相对 tic 与同 tic 顺序 |
| 读取频率 | 0/1/多次 snapshot/framebuffer 读取下 gameplay 轨迹一致；音频设备静音与逻辑禁声分别记录 |
| 画面/声音 | 可用截图/实际收听佐证；不以像素相似或音频波形相同代替模拟验证 |
| 差异处理 | 输出最早不同 tic、字段、两端值、前序输入、配置/资源身份；先查初始化/调度/裁剪依赖，不靠地图特例修补 |

RNG 不合并成一个 seed，非 mobj thinkers 不仅靠 entity_count 检查。内核退出/超时由外部监督器判失败，退出码为 0 也须有完成记录和期望断言。

## 5. Execution / 执行规模、入口与记录

建议每类确定性机制至少覆盖触发前、触发中、稳定后，起始规模 350 tic，不够覆盖周期时延长。保存续跑每支路至少 350 tic 是既有 M0 交接要求。建销先跑 M0 的 10 次烟测，收口建议扩到 50 次并记录每次销毁后的内核分配/句柄和进程工作集趋势；再做不少于 30 分钟的真实会话/换图观察。后两项是待实施测量的建议规模，不是已冻结性能保证。

性能记录 core tic、观察序列化、桥接复制、帧缓冲、音频缓冲/延迟、积压与内存；注明硬件、窗口、资源、实体/几何规模及 p50/p95/峰值。35 Hz 的间隔不能全算作允许内核耗时；目标预算在实际机器测量后填写，不以没有崩溃当性能通过。
